# 四色图志：体验与内容增强方案

> 版本：1.0 · 日期：2026-10-13 · 状态：待实施的后续设计。
> 本文将六项增强方向落实为产品流程、内容规格、工程边界与验收计划，不代表功能已经完成。
> 基线：[完整实现方案](implementation-plan.md)、[实现状态](implementation-status.md)；美术起点为 [PR #4：四章插画样板与图志美术优化](https://github.com/mingzhangyang/four-colors/pull/4)。编写时 PR #4 尚未合并，相关实现阶段须在其合并或兼容整合后开始。

## 1. 目标与范围

核心目标是让玩家从“完成一道涂色题”进入“修复一本有地方特色的图志”的体验。每关提供一个清楚的观察点，每章形成一次有起伏的旅程，完成的地图成为值得保留的作品。

优先改善三个结果：玩家能辨认自己所在的章节；能理解关键推理并逐渐减少对提示的依赖；完成后愿意停留观赏、继续下一页或保存作品。是否达到这些结果，需用试玩验证，不以插画数量或动画复杂度代替。

| 增强项 | 本轮设计的交付目标 | 优先级 |
| --- | --- | --- |
| 全章节美术完整度 | 32 张主线地图获得与地形匹配的章节插画，解题、收藏、缩略图及导出保持一致 | 高，先第一章 |
| 章节完成仪式感 | 八关逐步恢复一幅章节全景，四幅全景组成全册展示 | 高，先第一章 |
| 谜题节奏与个性 | 逐关标注学习目标、观察点、节奏角色与提示策略，审计重复与难度跳跃 | 高 |
| 提示教学能力 | 保留现有三层提示，增加可解释的关系高亮与证据约束 | 中高 |
| 手机操作与观赏 | 解题保持地图面积；完成后提供清爽、可退出的观赏模式 | 高 |
| 收藏个人表达 | 命名、精选配色、可选题签与日期、稳定的导出构图 | 中 |

保持 32 主线、8 短篇与编号每日题库的基本结构。暂不增加账号、联网同步、排行榜、体力、连续签到奖励、社交信息流或无限生成关卡。章节修复不增加新的解锁门槛，提示不减少美术奖励。

## 2. 已有基础与新增工作

现有规格和实现已经包含三层提示、完成地标显现、章节配色、收藏改色、PNG 导出、减少动态模式和全册展示入口。后续应沿用这些机制，而不是另建一套完成判定、提示服务或收藏存档。

PR #4 在 FC01、FC16、FC23、FC32 上建立四章插画样板，并共享地图、缩略图与导出的矢量路径；补充了章节扉页、边界层次和纸张样式。本方案进一步解决内容覆盖、章节连续感、提示解释和作品呈现。

现有全册地图拼图与新增的“章节风景全景”是两种不同内容：前者展示玩家完成的关卡地图，后者是随进度恢复的章节插画。界面应分别称为“地图总览 / Map Overview”和“图志全景 / Atlas Panorama”，不要用同一个标题暗示它们是一张地图。

## 3. 体验原则

1. **推理始终清晰。** 区域边界、冲突、固定印章、目标和当前选择的辨识度高于装饰。不可用房屋轮廓或河岸暗示不存在的邻接。
2. **每章具有自己的生活场景。** 通过地貌、建筑、植物和构图建立区别，颜色只是其中一层。
3. **奖励来自完成与表达。** 使用提示也能完整修复章节；独立完成标记保持独立记录，不决定作品是否完整。
4. **动画不控制事实。** 完成、解锁与保存先更新；动画可跳过、可中断，不能阻塞下一关或让刷新丢失进度。
5. **移动端优先。** 解题控件随手可达，作品观赏可以收起操作，但退出入口必须明确。
6. **一个事实来源，多种呈现。** 逻辑色、关卡进度、收藏颜色与插画数据各有明确归属，避免地图与导出各维护一份美术。

## 4. 全章节美术完整度

### 4.1 四章视觉语言

| 章节 | 场景与元素 | 构图倾向 | 应避免的问题 |
| --- | --- | --- | --- |
| 晨光原野 | 村舍、风车、篱笆、谷堆、果树、田畦 | 疏朗、暖白留白、顺地块方向的小聚落 | 装饰田埂被误认为可填区域边界 |
| 海湾城镇 | 帆船、灯塔、码头、仓屋、海鸟、波纹 | 水陆分层、岸线节奏、靠岸布局 | 船跨越可填区域；背景海域被误认为漏涂 |
| 折叠山谷 | 山峰、松林、桥梁、瀑布、层叠地形 | 纵深、疏密对比、与翻面视图相适配 | 等高线盖住真实边界；桥暗示额外邻接 |
| 万象花园 | 亭子、喷泉、花圃、庭门、池鱼、树列 | 克制的对称、庭院组团、局部镶嵌 | 纹样太密，压过双色交换预览和目标印章 |

每章先形成至少 6 类可复用元素与 2 组组合场景。数量是素材准备目标，不是每张地图的配额。每关指定一个主构图和少量次要点缀；小区域可以完全留白，不为了覆盖率挤入微小插画。

### 4.2 内容生产方法

先用地图的安全空间产生候选位置，再由美术布局数据选择位置、尺度、朝向和组合。不能把“按区域面积排序，轮流放图标”作为全章节最终构图。

插画优先使用可复用 SVG 路径。纯装饰不进入谜题主数据，不改变关卡 revision 或校验值；美术内容有自己的版本。若确需修改几何或规则，应另行走关卡版本与存档兼容流程。

每幅插画需声明包含描边的实际边界。自动验证其完整包围范围位于安全区域内，并避开固定印章、目标、区域标签及交互反馈的位置。曲线、旋转和缩放后的边界都必须计算；不能只验证锚点在多边形内部。替代视图逐份审核，不能沿用原视图的坐标。

### 4.3 显示层次

| 状态 | 插画行为 |
| --- | --- |
| 正在解题 | 区域内插画隐藏；纸张与外围章节装饰保持低对比 |
| 本次完成 | 完成状态先落地，插画在约 400–800ms 内分批显现；控件立即可用 |
| 已完成地图重新打开 | 直接显示与当前完成状态相符的画面；不重复长庆祝 |
| 撤销导致当前局面未完成 | 地图回到解题表现；历史完成记录及章节修复不倒退 |
| 收藏配色 | 始终可见，不依赖配色是否满足原题规则 |
| 减少动态 | 直接显示最终状态，提供文字反馈 |

地图、缩略图和 PNG 应使用同一份图形与布局；小尺寸可按明确的细节等级省略次要线条，不得换成无关图案。夜间界面保持“灯下纸页”，导出默认采用适合分享与打印的浅色纸张。

## 5. 章节全景与完成仪式

### 5.1 全景是什么

每章创作一幅独立风景插画，并划分为 8 个美术片段，分别对应该章的 8 个关卡 ID。所有片段组成连续风景，但不形成新的可玩区域。

**不把八道谜题的逻辑地图硬拼接。** 不增加跨关卡邻接，也不要求不同关卡的逻辑色编号在全景接缝处一致。全景使用章节预设配色，单页作品与地图总览保留玩家实际配色。界面说明“全景随修复进度显现”，不暗示它是玩家颜色的拼接结果。

例如第一章可是一幅由田野、村道、晒谷场与风车构成的乡村景象；完成 FC07 后，风车对应的片段恢复。具体片段位置由全景构图决定，不必按八等分网格机械排列。

### 5.2 状态与入口

- 未完成片段以淡线稿表示，不可用低对比方式隐藏全部进度信息；同时显示“已修复 3/8 页”。
- 完成片段显示正式颜色。任意顺序完成均映射到相应片段；重复完成不会重复计数。
- 进度从已经验证的主线完成记录派生，不另存一套章节完成数。提示辅助完成与独立完成都计入修复。
- 章节页展示全景预览及“查看全景”。从未完成片段进入关卡仍遵守现有解锁规则，全景不能成为绕过解锁的入口。
- 单关完成后保留“下一页”为主操作，并提供“看看图志”次操作；不强制跳去章节页。
- 完成第八个片段时，提供一次可跳过的通章展示及“下一章”“观赏全景”“返回图志”。全景随时可再次观看。
- 四章全部完成后，解锁四幅风景的全册展示和导出。它与已有地图总览并列存在。

### 5.3 恢复与异常行为

首次进入新版时，老玩家已有完成记录应立即恢复对应全景，不播放八次补发动画。完成记录存在但缺少解题配色时，全景仍可恢复，因为它不依赖该配色；单页缩略图则继续采用明确的预览回退。

庆祝是否看过只影响展示，不影响完成事实。若需要持久化，可存按章节 ID 和全景版本标识的可选展示记录；缺失时只允许适度补播一次。切后台、刷新或退出不会撤销解锁。美术加载失败时显示文字进度和重试入口，下一关继续可用。

导出未完全修复的全景时，保留未完成片段的线稿与进度说明；不把隐藏片段提前着色。完整章节与全册作品才使用“已修复”印章。

## 6. 谜题节奏与个性

### 6.1 审计方法

为每关补充设计侧资料：主要概念、预期观察点、容易产生的误解、一次有意义的决策、提示依据、预计体验时长、章节节奏角色。它们供策划与测试使用，不全部展示给玩家。

审核不能只看区域数或求解器节点数。要观察玩家是否读懂地图、是否能解释刚才的操作、是否通过盲试成功，以及重复改色来自有意推理还是操作误触。

保留已有普通关 2–6 分钟、入门更短、后期精选关 6–10 分钟的设计目标，作为试玩参考而非倒计时或强制验收阈值。不能把少量试玩的均值当作全体玩家难度结论。

### 6.2 第一章逐关目标

以下是基于现有关卡名称与规格的体验目标，实施时需逐图核对，不表示当前每关已经达到目标。

| 关卡 | 节奏角色与观察目标 | 美术建议 | 验收关注点 |
| --- | --- | --- | --- |
| FC01 四块田 | 无文字负担地理解选色、填色与相邻不同色 | 大块田野、村舍，疏朗 | 第一次误涂能够被理解和纠正 |
| FC02 篱笆两侧 | 练习观察共同边界 | 篱笆与树木只在安全空间点缀 | 装饰不产生假边界 |
| FC03 只在角上遇见 | 明确仅角点接触可以同色 | 构图避开中心角点 | 玩家能指出为什么对角同色合法 |
| FC04 三色就够 | 发现不必用满四种颜色 | 三组主要景物 | 三色是可发现的性质，普通关仍接受合法四色解 |
| FC05 重复的颜料 | 在不相邻的地块复用颜色 | 不同田地共享景物母题 | 不把同色复用误读为颜色数量奖励 |
| FC06 晒谷场 | 先观察关系较多的地块，再决定颜色 | 较集中的场景，保留空白 | 推理来自邻接而非某个区域总在画面中心 |
| FC07 风车下 | 综合运用、允许改色和撤销 | 风车作为章节视觉记忆点 | 避免和 FC06 仅区域数不同；发现重复则单独修订关卡 |
| FC08 第四枚印章 | 用紧凑的四区域关系带来“确实需要第四色”的收束 | 印章与村落收尾、全景完成 | 让玩家看见四个区域两两相邻，区域数减少不代表结尾失去力度 |

FC08 的第四色来自图结构本身，不应新增“必须选遍四个按钮”的伪目标。第一章不提前引入双色交换。提示文案不能要求唯一解或将某份见证答案作为标准配色。

### 6.3 后三章

海湾侧重固定线索和周边颜色的协调，FC16 保留中心腾色的记忆点；山谷强化真实邻接与形状的区别，FC23/FC24 保留结构相同、外形不同的发现；花园围绕完整双色连通分量建立理解，FC26 保持小样教学，不为视觉统一强行增加区域。

先审计和调整表达、构图及提示，再决定是否需要改题。确需改题时，单独提交几何、可解性、难度证据与 revision 兼容设计；已发布每日题目、编号和起始日不因本方案改写。

## 7. 提示的教学能力

沿用现有“观察 → 限制 → 一步建议”，增强每层的解释与地图对应关系。

| 层级 | 应回答的问题 | 展示方式 |
| --- | --- | --- |
| 观察 | 现在值得看哪里？ | 指向少量相关区域或一条真实共享边；不直接泄露整图 |
| 限制 | 这些关系意味着什么？ | 高亮相关邻居，文字说明已有颜色或约束，提供逻辑色的纹理标识 |
| 建议 | 下一步可以怎么做？ | 推荐一次合法操作；用户自行执行，不默认自动填入 |

示例文案必须按真实状态生成：“这块地的相邻区域已经用了三种颜料，看看还剩哪一种。”仅在完整有效约束足以支持时，才进一步说“这里只能使用……”。求解超时、仅找到一个解或局部候选唯一，不足以证明全局唯一。

提示引擎输出结构化原因，例如相关区域、共享边、排除的逻辑色、建议命令与证明状态；渲染层负责文案和高亮，不在界面里重新求解。无解局面优先解释冲突或指出需要回看已有配色；交换提示解释完整分量及固定印章阻挡，不截断分量来制造可行操作。最少重涂/最少交换仅在最优性已证明时使用。

高亮不得占用区域命中层，不能只靠颜色或闪烁表达。玩家改色、撤销、重做、重开、切关或翻面后，旧解释应失效或按当前视图重新计算投影。保持现有 sessionId、puzzleRevision、stateRevision 校验和 Worker 取消/超时机制；错误与超时提供重试而不是伪造解释。

屏幕阅读器应读出同一组关系。切换语言后文案完整更新，区域 ID 与逻辑色对应不变。辅助记录沿用既有语义，不因视觉高亮新建另一套“是否使用提示”状态。

## 8. 手机操作与作品观赏

### 8.1 解题界面

保持地图为主体，四颜料、撤销和工具入口易触达。附加说明采用紧凑文本或可展开区域，不长期压缩地图。底部适配安全区及浏览器动态工具栏；横屏短视口延续侧边工具布局。

新增控件命中目标以至少 44×44 CSS px 为目标；密集地图区域继续使用已有命中与区域列表方案。不得通过缩小区域来腾出装饰空间，也不能让虚拟键盘弹出后把保存/取消按钮挤出可见区域。

### 8.2 完成与观赏流程

| 状态 | 主要内容 | 可用操作 |
| --- | --- | --- |
| 解题 | 地图、颜料和必要状态 | 正常操作、撤销、工具 |
| 完成 | 地图显现插画，紧凑完成条 | 下一页、观赏、收藏/分享 |
| 观赏 | 地图或章节全景、克制的题签 | 明确的退出按钮；轻触可显示其他操作 |
| 返回解题/收藏 | 恢复原来的控件与焦点 | 保持颜色、历史和滚动位置合理 |

完成后不强制进入全屏，也不在玩家准备点“下一页”时自动移动按钮。观赏模式由明确操作进入；退出按钮始终可发现，不以双击、长按或隐藏手势作为唯一出口。观赏时冻结涂色输入，点击作品不能误改色；收藏编辑仍是独立的可编辑状态。

浏览器返回、键盘 Esc 和可见退出按钮都应按一致的状态模型退出观赏，返回原入口，并恢复焦点。不强依赖 Fullscreen API，以适配移动 Safari。首次进入不自动聚焦文本输入；输入字号至少 16px，防止 iOS 自动放大，同时保留用户缩放能力。

### 8.3 验收视口

至少覆盖 320×454、375×553、390×664、839×360 和常规桌面；验证横竖屏切换、安全区、中文/英文、明暗主题、减少动态、高对比与键盘导航。模拟浏览器检查之外，发布门槛仍包含 iOS Safari 真机操作；机器通过不能替代真机与读屏验收。

## 9. 收藏的个人表达

### 9.1 作品命名与配色

收藏作品增加可选名称：去除首尾空白后最多 40 个用户感知字符；空名称显示原关卡名。粘贴长文字时明确反馈，保存和导出使用同一规范；不把 UTF-16 代码单元数当作汉字与 emoji 的字符数。名称按纯文本渲染。

先提供每章 3 组人工审定的配色，保留原章节配色和高对比方案。配色只映射逻辑色 0–3，不改区域颜色编号、固定色与规则。普通解题的辅助纹理及符号保持稳定；关闭纹理的纯画面选项放在收藏与导出中，不能悄悄影响解题辅助。

切换收藏配色时不覆写全局解题设置。编辑先保持在草稿中，明确“保存修改”和“另存作品”；取消恢复打开时的作品。改变收藏颜色、标题或配色不更新原关卡完成、独立完成和首次解题记录。

### 9.2 导出

首版提供“纯地图”和“图志装帧”两种模板，避免大量边框配置。装帧模板允许选择显示标题、保存日期、小印章与留白；使用纯色纸张和已加载矢量素材，不依赖外部字体或远程图片完成导出。

保存日期表示该收藏的首次保存时间，不冒充首次解题时间；缺少旧记录日期时隐藏，不伪造。日期按用户当前语言和本地时区格式化。预览与导出共用标题换行、缩放和截断规则，长标题、中文、英文及 emoji 都须检查。

默认长边 2048px，导出失败允许重试或降到 1024px，并保留草稿。批量/全册导出逐步绘制、及时释放临时画布和对象 URL，不同时创建大量高分辨率画布。平台不支持文件分享时提供 PNG 下载；取消系统分享不应显示“导出失败”。

章节全景与全册作品沿用同一装帧布局，但不混用单页收藏的颜色语义。分享文字默认保持无剧透；明确选择分享作品图时，预览应让用户知道图片包含完成配色。

### 9.3 兼容与存储

作品名称、稳定的 paletteId、模板选项等是收藏的可选元数据；不存在时回退到旧版外观。未知配色 ID 回退到章节默认配色，不能丢弃颜色数组或整条收藏。

扩展存档需同步更新校验、读写与往返测试，不能只在 UI 对象上添加字段。沿用单快照、写入失败反馈与多标签冲突处理。若需要提升 schema，必须显式迁移旧数据，不能借用当前“不认识 schema 就返回空存档”的兜底逻辑。保存失败时保留可重试草稿，不显示成功；外部存档替换前取消旧会话待保存任务。

## 10. 工程结构与边界

以下为职责建议，文件拆分应随真实复杂度进行，不为命名预先制造空模块。

| 层次 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 规则与内容 | 逻辑色、邻接、目标、完成判定、关卡版本 | 插画布局与庆祝动画 |
| 美术目录与布局 | 图形、边界、章节母题、每关/每视图布局、细节等级 | 改写颜色或完成记录 |
| 章节进度投影 | 从验证后的完成记录得到 8 个片段与通章状态 | 独立维护第二份完成计数 |
| 提示服务 | 生成建议、关系证据和证明状态 | 直接操作 DOM 或替用户提交动作 |
| 地图与作品渲染 | 解题、观赏、缩略图、全景和导出投影 | 重新判定解题或私自迁移存档 |
| 收藏与存储 | 草稿、元数据校验、保存结果、冲突处理 | 动画结束后才决定完成是否有效 |

`game.js` 保持流程编排；可将逐渐增长的作品布局、全景投影及收藏草稿职责抽出，避免持续堆叠分支。SVG 与 Canvas 共用图形描述和布局计算，适配各自绘制 API；不要求两种渲染技术共用 DOM。

美术按章节懒加载。全景只在章节页或观赏时加载，不让首次进入 FC01 下载四章插画。异步结果绑定当前路由/会话令牌；切章后返回的旧资源不能覆盖新页面。纯装饰加载失败应可降级。

首屏 JS gzip 保持不超过现有 150 KB 预算；空闲时无持续 requestAnimationFrame，模型命令延续现有性能门槛。为新增全景与素材单列加载大小、冷启动和导出峰值内存记录，在第一章实测后确定可复用的资源预算，不把未经测量的数字写成已达成指标。

## 12. 验收矩阵

| 编号 | 验收对象 | 可检查的通过条件 |
| --- | --- | --- |
| A01 | 插画安全 | 所有已覆盖主线及替代视图，含描边的插画不越界、不压印章/目标；真实边界无遗漏与重复 |
| A02 | 美术辨识 | 隐去章节标题后，试玩者可根据场景描述章节特点；记录误认原因并调整，不能仅靠色相区分 |
| A03 | 章节进度 | 0/8、部分、8/8、乱序、重复完成均正确；辅助完成正常计入；重玩和撤销不抹去历史修复 |
| A04 | 老玩家升级 | 已完成记录即时派生全景；缺少 solution 不阻止全景恢复；不播放补发动画队列 |
| A05 | 完成生命周期 | 动画中返回、切后台、刷新、跳过后完成记录一致，主操作不被动画锁住 |
| A06 | 提示可信 | 多解、无解、少色限制、固定色与交换锁定正确；未证明最优不宣称最优，超时可恢复 |
| A07 | 提示投影 | 改色/撤销/翻面/切关后无旧高亮；高亮不拦截输入；文字与读屏关系一致 |
| A08 | 观赏模式 | 作品不能被误涂；退出、Esc、浏览器返回恢复正确状态与焦点；无隐藏手势依赖 |
| A09 | 手机与可访问性 | 指定视口无关键控件溢出，旋转不误涂；iOS 真机、中文字体、键盘与读屏人工验收通过 |
| A10 | 收藏兼容 | 旧字段缺失/未知配色可回退；往返保存不丢字段；写入失败保留草稿，多标签不覆盖新数据 |
| A11 | 输出一致 | 同一作品的颜色、布局、标题在预览和导出对应；窄长图和长文本不裁切；未修复全景不泄露隐藏片段 |
| A12 | 性能与资源 | 通过现有首屏、命令和空闲帧门槛；记录章节加载与导出内存；失败路径可降级且无资源泄漏 |
| A13 | 第一章节奏 | 逐关有可解释的设计目标，FC03 角点、FC04 可少色、FC08 必需四色的表达不冲突；重复与卡点有处理结论 |

测试分层：纯函数验证进度投影、元数据与提示证据；几何测试验证美术安全；浏览器测试覆盖状态切换、输入、存档和导出；人工复核构图、字体、色觉辅助和真机手感。不要用截图像素一致替代规则测试，也不要用自动测试通过替代美术判断。

建议邀请 5–8 名未玩过本项目的人完成第一章，包含手机用户与不同解谜经验者。记录第一次有效操作、误触、卡点、提示后能否复述理由、通章后是否理解全景与作品区别，以及是否愿意继续。首轮目标是发现问题，不据此宣称统计上的留存提升；若后续增加线上数据采集，应另行设计最小事件和隐私边界，不采集作品标题或逐步配色内容。

## 13. 风险与取舍

| 风险 | 处理方式 |
| --- | --- |
| 插画数量增加但地图仍像重复贴图 | 对每关进行主构图审核，使用地形安全布局与疏密变化，允许留白 |
| 全景看起来像新的待解谜题 | 独立入口、进度说明与观赏交互；不出现可涂颜料工具 |
| 庆祝打断连续游玩 | 默认紧凑反馈，主动观看、可跳过；减少动态直接落到最终状态 |
| 提示解释比求解结果更武断 | 原因随证据输出；禁止 UI 自行推断“唯一”“最少” |
| 为统一美术破坏关卡质量 | 美术适配几何，题目变更单独审计，保留标志性小样与反例 |
| 收藏功能造成存档丢失或首次记录污染 | 草稿与解题记录分离，验证可选字段，显式迁移与失败恢复 |
| 新资源拖慢首次进入 | 按章节/入口加载，先交付第一章实测，再推广预算 |

设计层面的默认决定已经明确：全景使用章节预设配色、进度来自历史完成、观赏主动进入、普通关继续接受任意合法解。实施时仍需通过第一章实测决定每页插画密度、全景具体构图与资源预算；这些属于内容打磨，不应成为重新扩张功能范围的理由。
